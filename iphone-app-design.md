# iPhone app design (derived from the Mac app findings)

Goal: an iPhone personal-finance app with the same functional scope as Debit & Credit for Mac. This is a clean-room design from observed behavior; use original names, icons, and visuals.

## Stack (proposed)
- SwiftUI, iOS 17+, SwiftData (or Core Data if you want the Mac schema 1:1), CloudKit private database for sync. Charts framework for reports. WidgetKit and App Intents for widgets and Siri.
- Domain logic in a local Swift package (`LedgerCore`) with no UI imports, so it is unit-testable and shareable with a future Mac target.

## Data model (from the Mac Core Data schema, simplified)
Account (folder, type, currency, balances, credit limit), AccountFolder, Transaction (+ Split, Attachment), RecurringTransaction, Budget (+ BudgetLimit history), Plan (+ PlanPeriod, PlanUnit, PlanItem), Category (tree), Payee (+ Location), Tag, Description, ImportRule, Currency, Tombstone for deletes. Keep `recordName`, change tag and soft-delete date for CloudKit.

## Navigation
Tab bar: Accounts, Activity, Budgets, Plans, Scheduled. Reports, Settings, Import/Export and Reconciliation live under a "More" sheet from Accounts. A floating "+" opens the Add Transaction sheet on every tab.
Mac to iPhone mapping: account sidebar becomes the Accounts tab; transaction list plus detail becomes Activity push navigation; Mac secondary windows become sheets.

## Screens
1. **Accounts**: net worth header (excludes accounts flagged excluded), folders with collapsible accounts, balance per account, cleared vs uncleared toggle, credit accounts show available credit.
2. **Activity**: grouped by day, search and filters (account, category, tag, pending), swipe to delete or mark reconciled, detail with splits, attachments, notes, location.
3. **Add transaction**: type (expense, income, transfer), amount, payee (suggest by nearby location), account, category (or splits), tag, date, repeat, attachment (scan receipt with Vision).
4. **Budgets**: progress bars per budget, remaining amount, period, carry-over, over-budget badge.
5. **Plans**: planned versus actual per month, income/expense/net wealth, suggestions from budgets, scheduled items, and last three months.
6. **Scheduled**: upcoming list, skip, execute now, edit amount.
7. **Reports**: category trends and budget reports with Swift Charts.
8. **Settings**: iCloud sync and sharing, lock (Face ID and PIN), backups, currencies, import/export.

## Core logic to reimplement (see findings Part 2)
- Next date: day, week, month, year by interval from the original start date (no drift), plus "nth weekday of month" types; loop until after a reference date.
- Balances: signed sum of amounts per account, with a pending toggle; folder totals convert currencies via rate.
- Budget period: step from start date by repeat unit; sum spending by category and tag filters, optional pending, converted to the budget currency; limit from history; carry-over and refunds tracked.
- Plan: annual amounts divided monthly, one-offs in payment month, per-period actual-vs-planned comparison.
- Recurring processing: create transaction or transfer (source and destination amounts), optional cashback transaction, advance next date, keep upcoming rows ahead of a threshold.

## Build order
1. LedgerCore package with models and tests for date stepping, balances, budget period.
2. Accounts, Activity and Add flows with local persistence.
3. Budgets, Scheduled, Plans.
4. CloudKit sync, widgets, App Intents.
5. Import (CSV, OFX, QIF), reports, reconciliation.

## Open decisions
Native SwiftUI versus cross-platform; whether the Mac schema must stay compatible; how much of premium and sharing to include in v1.

# Дорожная карта после первой сборки (обновлено 2026-10-19)

Приложение называется «Срудж Богдан». Сделано в первой сборке: счета, операции (расход, доход, перевод), бюджеты, платежи по расписанию, планы по месяцам, пакет `LedgerCore` (19 тестов). Ниже то, чего не хватает, в порядке важности. Всё пока только запланировано, ничего из этого списка не реализовано.

## Этап 0. Валюты (блокирует всё остальное)

### Что сломано сейчас (найдено в коде и при ручной проверке)
- «Всего» на экране «Счета» складывает суммы счетов как есть, без пересчёта: 100 долларов и 100 рублей дают «200 ₽».
- Любая сумма без привязки к счёту показывается в рублях по умолчанию.
- Бюджеты и планы считают все операции в одной «куче», курс всегда равен 1.
- Перевод между счетами в разных валютах невозможен: вводится одна сумма, на второй счёт приходит то же число.
- В форме новой операции не видно, в какой валюте вводишь сумму.
- Количество знаков после запятой одинаково для всех валют (для иен и тенге нужно своё).

### Как должно работать
- **Основная валюта** в настройках (по умолчанию из региона телефона). В ней показываются «Всего», итоги папок, бюджеты по умолчанию и планы.
- **Справочник валют и курсов**: код, символ, знаков после запятой, курс к основной валюте, дата курса. Курсы подтягиваются из интернета автоматически, ручная правка остаётся запасным вариантом (решение 1 ниже).
- **Пересчёт везде через `LedgerCore`**: «Всего», бюджеты, планы, отчёты. Операция хранит сумму в валюте своего счёта; пересчёт делается на лету по курсу.
- **Подсумма по валютам**: под «Всего» список «в долларах 1 200, в рублях 80 000» (сворачиваемый).
- **Перевод между валютами**: два поля, «списано» и «зачислено», курс считается и показывается; можно поправить любое из полей.
- **Форма операции**: рядом с суммой всегда виден код валюты счёта; при смене счёта он меняется.
- **Бюджет** имеет свою валюту: операции в других валютах пересчитываются в неё.
- Курс операции хранится в самой операции (решение 4 ниже).
- Тесты: «Всего» с тремя валютами, перевод USD→RUB с двумя суммами, бюджет с операциями в двух валютах, округление для валюты без копеек.

## Этап 1. Дыры в основе
- **Редактирование**: сейчас операции, счета, бюджеты и пункты плана можно только создать и удалить. Нужен экран операции с правкой всех полей.
- **Экран операции**: детали, заметка, дата, статус «проведена/ожидает», связанная половина перевода.
- **Счета**: правка, папки, порядок, скрытие, переключатель «не считать в общем капитале» (поле есть, кнопки нет), тип счёта (карта, наличные, сбережения, кредит).
- **Категории**: создание, правка, удаление, подкатегории, порядок. Сейчас набор зашит при первом запуске.
- **Метки (теги) и получатели**: подсказки при вводе, запоминание последней категории получателя.
- **Операции**: фильтры (счёт, категория, метка, статус), итог по выбранному, пометка «сверено».
- **Деление операции** на несколько категорий.
- **Настройки**: основная валюта, курсы, категории, о приложении.
- **Удаление счёта**: спросить, что делать с операциями и со второй половиной переводов (сейчас вторая половина остаётся «висеть»).
- **Начальный остаток** сейчас создаётся как обычная операция «сегодня»; сделать отдельным понятием, чтобы не портил отчёты.

## Этап 2. Расписание
- Список будущих операций вперёд на заданный срок, а не только ближайшая.
- Уведомления с кнопками «Выполнить» и «Пропустить»; значок с числом просроченных.
- Переводы по расписанию, кешбэк, автоматическое проведение (по желанию).
- Полная правка платежа (сейчас можно менять только сумму).

## Этап 3. Бюджеты
- Правка, перенос остатка на следующий период (логика в `LedgerCore` есть, в интерфейсе нет), история лимитов, фильтры по меткам.
- Экран бюджета: операции, график по дням.
- Период «каждые N» (сейчас только «каждый»), счётчик бюджетов с перерасходом.
- Известный долг в коде: категории в `LedgerCore` идут по UUID, а в моделях по внутреннему идентификатору, поэтому в `BudgetsView` стоит обходной фильтр. Добавить каждой категории стабильный UUID.

## Этап 4. Планы
- Правка пунктов и сумм по месяцам, «предложить план» из бюджетов, расписания и последних трёх месяцев.
- Прогноз капитала по месяцам.
- Факт считать с учётом валют (после этапа 0).

## Этап 5. Отчёты
- Траты по категориям (круговая и по месяцам), доходы и расходы по периодам, бюджеты по периодам. Swift Charts.

## Этап 6. Данные
- Импорт и экспорт CSV, затем OFX/QIF с правилами «получатель → категория» и поиском дублей.
- Резервная копия и восстановление.

## Этап 7. Безопасность
- Face ID или PIN, размытие экрана в переключателе приложений, PIN в связке ключей.

## Этап 8. Синхронизация и расширения
- iCloud (CloudKit, личная база), виджеты, Siri и ярлыки, календарь, сканирование чеков, общий доступ.

## Качество и оформление (идёт параллельно)
- Кнопка «+» закрывает нижние строки списков: добавить отступ внизу.
- Тексты сейчас зашиты по-русски в коде; вынести в таблицу строк, чтобы можно было добавить языки.
- Иконка приложения (оригинальная), темная тема, крупный шрифт, озвучка суммы для VoiceOver.
- Тесты на уровне приложения (создание счёта, операция, перевод, расписание), не только для `LedgerCore`.
- Миграции данных: пока схема меняется свободно, перед выпуском зафиксировать версию схемы.

## Принятые решения (2026-10-19)
1. **Курсы валют: автоматически из интернета.** Приложение само подтягивает курсы с внешнего сервиса. Это единственное исключение из правила «данные только на устройстве»: наружу уходят только коды валют, суммы и операции не отправляются. Если интернета нет, используется последний сохранённый курс, дату курса видно в настройках; ручная правка курса остаётся как запасной вариант. Конкретный сервис курсов выбрать при реализации (нужен бесплатный, без ключа с персональными данными) и записать сюда.
2. **Основная валюта: спрашивать при первом запуске.** Один экран выбора до начала работы, потом меняется в настройках. Смена основной валюты пересчитывает отображение, но не искажает сохранённые курсы операций.
3. **Языки: русский и английский.** Все тексты сразу выносятся в таблицу строк (String Catalog), в коде литералов нет.
4. **Курс операции хранится в самой операции.** Каждая операция запоминает курс на момент создания; отчёты и бюджеты по прошлым периодам используют его и не меняются при смене курса. Для суммы «Всего» по текущим остаткам используется свежий курс.
5. **iCloud: после отчётов и импорта** (этапы 5 и 6), то есть после того как схема данных устоится.

Что это меняет в плане:
- Этап 0 расширяется: модель валюты и курсов, поле «курс» у операции, загрузка курсов, экран выбора основной валюты, таблица строк на двух языках.

# Дополнения к этапу 0 (2026-10-19, по правкам владельца)

Этап 0 теперь включает три дополнительные части. Порядок внутри этапа: валюты (в том числе BYN), категории, кредитные счета.

## A. Белорусский рубль (BYN) с новым знаком

- BYN есть в списке валют наравне с остальными. Оба сервиса курсов его отдают, в том числе на прошлые даты (проверено 2026-10-19).
- Нацбанк Беларуси утвердил графический знак: буква «Б» с горизонтальной чертой (постановление №25 от 27 января; источник: новости myfin.by и devby). Кода в Unicode под него найти не удалось, системные шрифты iOS показывают «Br».
- Поэтому знак рисуется в приложении как векторная картинка (шаблонное изображение, красится в цвет текста, масштабируется вместе с шрифтом). Там, где символ валюты выводится в интерфейсе, вместо текста «Br» подставляется эта картинка. В чисто текстовых местах (экспорт в CSV, уведомления, VoiceOver) остаётся «Br» или код BYN.
- Для озвучки VoiceOver: «белорусский рубль».
- Риск: знак нарисован по описанию «Б с чертой», а не по официальному макету. Если у владельца есть официальный файл знака, заменить им нашу картинку (файл подставляется в один ресурс, остальное не меняется).
- Валюты с собственным знаком в общем справочнике хранят поле «имя картинки знака»; пустое значение означает обычный текстовый символ. Так можно добавить другие знаки позже.

## B. Категории

Сейчас набор категорий зашит при первом запуске и не редактируется. Нужен полный функционал:
- Экран «Категории» в настройках: два раздела (расходы и доходы), дерево с подкатегориями (до двух уровней), перетаскивание порядка.
- Создание и правка: название, тип (расход или доход), родитель, иконка (символ из набора), цвет.
- Создание «на месте»: в выборе категории при вводе операции есть строка поиска и пункт «Новая категория», которая сразу выбирается.
- Удаление: если категория использована, спрашиваем, куда перенести операции, или архивируем её (скрыта из выбора, в старых операциях остаётся). Слияние двух категорий.
- Сортировка в выборе: недавно использованные сверху, затем по частоте.
- Бюджеты и планы: выбор родительской категории включает все её подкатегории.
- Стандартный набор категорий создаётся на языке интерфейса (русский или английский) и после этого полностью принадлежит пользователю.
- Техническое: каждой категории добавляется стабильный идентификатор (UUID), это заодно убирает обходной фильтр в бюджетах.
- Тесты: подкатегории в бюджете, перенос операций при удалении, слияние.

## C. Кредитные счета (возобновляемые кредитные линии)

Сейчас «кредитный счёт» это только лимит и строка «Доступно». Нужна полноценная кредитная линия. Тип счёта становится явным: карта, наличные, сбережения, кредитная линия.

### Поля кредитной линии
- Кредитный лимит.
- Процентная ставка (годовая) для информационной оценки процентов.
- День выписки (когда банк закрывает расчётный период) и срок до обязательного платежа.
- Льготный период в днях (беспроцентный срок) и правило его отсчёта: от даты выписки или от даты покупки. Банки считают по-разному, поэтому по умолчанию «от даты выписки», но настраивается.
- Минимальный платёж: процент от долга и минимальная сумма в рублях (оба поля настраиваются).
- Комиссии: годовое обслуживание (по желанию), записывается как расход в категорию «Проценты и комиссии».

### Что показывает экран кредитной линии
- Три цифры крупно: Долг, Доступно (лимит минус долг), Лимит; полоса «использовано N%», красная при превышении порога или лимита.
- Блок «Ближайший платёж»: дата, минимальный платёж, и сумма, которую нужно внести, чтобы не платить проценты (если действует льготный период), с датой, до которой это нужно сделать.
- Оценка процентов за текущий период (по среднедневному долгу и ставке); помечена как «оценка», точные цифры у банка.
- История выписок: период, расходы, погашения, проценты, итог.
- Предупреждение при превышении лимита.

### Как ведётся учёт
- Покупка по карте: расход со счёта-кредитки в момент покупки, попадает в бюджет и отчёты как обычная трата.
- Погашение: перевод с обычного счёта на кредитку. В отчётах это не расход (иначе трата посчитается дважды), в Активности подписывается «Погашение».
- Проценты и комиссии банка: отдельная операция-расход в категории «Проценты и комиссии».
- Долг входит в общий капитал со знаком минус, лимит в капитал не входит (уже так).
- Для кредитки в валюте, отличной от основной, всё пересчитывается по правилам валют из этапа 0.

### Логика в `LedgerCore` (с тестами, пишутся первыми)
- Расчётный период по дню выписки (включая короткие месяцы).
- Дата обязательного платежа и конец льготного периода по выбранному правилу.
- Минимальный платёж: большее из «процент от долга» и «минимальная сумма», но не больше долга.
- Оценка процентов по среднедневному долгу.
- Сумма «погасить до даты, чтобы не платить проценты».
- Сценарии тестов: частичное погашение, полное погашение в льготный период, превышение лимита, покупка в день выписки, погашение в другой валюте.

### Чего пока нет (на потом)
- Напоминания о платеже уведомлениями (после этапа 2 «Расписание», сможем сделать платёж-напоминание регулярным).
- Снятие наличных с отдельной ставкой, кешбэк, рассрочки, кредиты с графиком (это другой тип счёта, не возобновляемая линия).

### Допущение, которое стоит проверить
Правила банков отличаются (когда начинается льготный период, как считаются проценты, как считается минимальный платёж). Поэтому всё это настраиваемо, а проценты показываются как оценка. Если у тебя конкретный банк, дай его правила, и можно сделать пресет.

# Состояние этапа 0 (2026-10-19, вечер)

Сделано и проверено в симуляторе (iPhone 15, русский язык, демо-данные) и тестами `LedgerCore` (35 тестов):
- Основная валюта выбирается при первом запуске; курсы грузятся из интернета (основной сервис fawazahmed0, запасной open.er-api.com), есть встроенный снимок курсов на 2026-10-18 для работы без сети. Курс сохраняется в операции; для операций задним числом курс подтягивается на их дату.
- «Всего» и итоги считаются в основной валюте с пересчётом, под ними «По валютам». Предупреждение, если для валюты нет курса.
- BYN со своим знаком «Б с чертой» (нарисован по образцу владельца, `App/Support/BynSign.swift`).
- Перевод между валютами: сумма зачисления предлагается по курсу, показывается курс, можно поправить.
- Бюджеты в своей валюте, планы в основной; факт считается по сохранённым курсам операций, подкатегории входят в родителя.
- Категории: экран управления, подкатегории, иконки и цвета, выбор с поиском и «недавними», создание на месте, перенос или архив при удалении, порядок.
- Кредитные линии: поля условий, экран с долгом, лимитом, использованием, минимальным платежом, датами выписки и платежа, суммой «погасить до даты, чтобы не платить проценты», оценкой процентов, историей выписок, кнопкой «Погасить» (перевод с другого счёта).
